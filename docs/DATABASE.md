# Database

PostgreSQL 18. One database (`restaurant_management_db`) for the whole platform,
with `restaurant_id` separating each restaurant's data and `outlet_id` where
outlet-level control is needed.

The schema is defined **only** by the SQL files in `backend/migrations/`.
This document describes what those files create.

## Migrations

| Command | What it does |
| --- | --- |
| `npm run migrate:create -- <name>` | Create an empty migration file |
| `npm run migrate:up` | Run every migration that has not run yet |
| `npm run migrate:down` | Undo the last migration only |

Each file has two halves, and both markers are required:

```sql
-- Up Migration
CREATE TABLE ...;

-- Down Migration
DROP TABLE IF EXISTS ...;
```

The tool records finished migrations in the `pgmigrations` table, so running
`migrate:up` twice is safe. Never edit `pgmigrations` by hand.

### Rules

1. Never create or change tables by hand in pgAdmin.
2. Never edit a migration that has already been pushed; write a new one.
3. Always write the `Down` half, so a mistake can be undone.
4. Every business table gets `restaurant_id` and the common columns below.

## Common columns

| Column | Type | Purpose |
| --- | --- | --- |
| `id` | `BIGINT GENERATED ALWAYS AS IDENTITY` | Primary key, generated by the database |
| `restaurant_id` | `BIGINT` | Which restaurant owns the row |
| `outlet_id` | `BIGINT` | Outlet, where needed |
| `status` | `VARCHAR(20)` + `CHECK` | Record/business status |
| `created_at` | `TIMESTAMPTZ DEFAULT NOW()` | When the row was created |
| `updated_at` | `TIMESTAMPTZ DEFAULT NOW()` | Maintained by a trigger |
| `created_by` | `BIGINT REFERENCES users(id)` | Who created the row |
| `updated_by` | `BIGINT REFERENCES users(id)` | Who last changed it |

`GENERATED ALWAYS` means ids cannot be supplied manually, which prevents
duplicate-key problems. `TIMESTAMPTZ` keeps times correct across timezones.

### `set_updated_at()` trigger function

Created in the first migration and reused by every table:

```sql
CREATE TRIGGER trg_<table>_updated_at
BEFORE UPDATE ON <table>
FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

It sets `updated_at = NOW()` on every UPDATE, so application code never has to.

## Current tables

Created by migrations 1–3 (Sprint 1).

### `restaurants`
The tenant table. Everything else belongs to a restaurant.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | BIGINT identity | Primary key |
| `name` | VARCHAR(150) | Required |
| `code` | VARCHAR(30) | Required, **unique** (e.g. `ABC001`) |
| `contact` | VARCHAR(20) | Optional |
| `email` | VARCHAR(150) | Optional |
| `address` | TEXT | Optional |
| `status` | VARCHAR(20) | `active` / `inactive` / `suspended` |
| common columns | | `created_at`, `updated_at`, `created_by`, `updated_by` |

A suspended restaurant blocks login for all of its users.

### `outlets`
Branches of a restaurant (future multi-outlet support).

| Column | Type | Notes |
| --- | --- | --- |
| `id` | BIGINT identity | Primary key |
| `restaurant_id` | BIGINT | Required → `restaurants(id)` |
| `name` | VARCHAR(150) | Required |
| `code` | VARCHAR(30) | Required, unique **within the restaurant** |
| `contact`, `address` | | Optional |
| `status` | VARCHAR(20) | `active` / `inactive` |

Index: `idx_outlets_restaurant_id`.

### `users`
Login accounts.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | BIGINT identity | Primary key |
| `restaurant_id` | BIGINT | **NULL = platform user (Super Admin)** |
| `outlet_id` | BIGINT | Optional |
| `name` | VARCHAR(150) | Required |
| `email` | VARCHAR(150) | Required, unique ignoring case (login id) |
| `mobile` | VARCHAR(20) | Optional, unique when present |
| `password_hash` | VARCHAR(255) | bcrypt hash, never the password |
| `status` | VARCHAR(20) | `active` / `inactive` / `locked` |
| `last_login_at` | TIMESTAMPTZ | Set on each successful login |

Indexes: `uq_users_email_lower` (unique on `LOWER(email)`),
`uq_users_mobile` (unique where mobile is not null),
`idx_users_restaurant_id`.

### `roles`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | BIGINT identity | Primary key |
| `restaurant_id` | BIGINT | **NULL = system role shared by all restaurants** |
| `code` | VARCHAR(50) | e.g. `CASHIER` |
| `name` | VARCHAR(100) | Display name |
| `description` | TEXT | Optional |
| `is_system` | BOOLEAN | True for the six built-in roles |
| `status` | VARCHAR(20) | `active` / `inactive` |

Unique: `(restaurant_id, code)` with `NULLS NOT DISTINCT`, so two system roles
cannot share a code. A restaurant can later add custom roles with its own id.

### `permissions`
Global: the application code decides which permissions exist.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | BIGINT identity | Primary key |
| `code` | VARCHAR(100) | Unique, e.g. `orders.create` |
| `module` | VARCHAR(50) | e.g. `orders` |
| `name` | VARCHAR(150) | Display name |

### `user_roles` and `role_permissions`
Link tables (many-to-many). Primary key is the pair of ids, and rows are removed
automatically (`ON DELETE CASCADE`) when the user or role is deleted.

```
users ──< user_roles >── roles ──< role_permissions >── permissions
```

### `pgmigrations`
Created and maintained by the migration tool. Do not edit.

## Relationships

```
restaurants ──< outlets
restaurants ──< users ──< user_roles >── roles ──< role_permissions >── permissions
restaurants ──< roles            (custom roles; NULL = system role)
```

### Conventions for new tables

- Table names: lowercase, plural, snake_case (`order_items`).
- Money: `NUMERIC(12, 2)`, never `FLOAT`, so rounding is exact.
- Quantities: `NUMERIC(12, 3)` where fractions are possible (kg, litres).
- Status columns: `VARCHAR(20)` with a `CHECK` list, not free text.
- Add an index on `restaurant_id` and on any foreign key used for lookups.
- Add the `updated_at` trigger to every table.
